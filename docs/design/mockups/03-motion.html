How do the vehicles move?

GTFS-RT feeds refresh every 15–30s. The feed gives you a position that is already a few seconds stale. What you do between polls is the difference between "a data readout" and "a living thing on the wall". Watch all three — they use the same made-up feed at the same update rate.

POLL
RAW — redraw on each poll

A — Snap to feed

Draw exactly what the feed says. Dot teleports every poll, then sits still.

Truthful: completely — never shows a position no agency reported.
Art: poor. A static screen that twitches every 20s reads as broken, not alive.
Cost: zero. This is the free option.

POLL
TWEEN — glide last → current

B — Tween between polls recommended

Animate from the previous reported point to the new one over the poll interval, following the track polyline rather than a straight chord.

Truthful: yes, but always ~one interval behind reality — you're animating history.
Art: strong. Continuous motion, no guessing.
Cost: low — needs each vehicle snapped to a distance-along-shape so it glides on rails, not through buildings.

POLL
PREDICT — white = estimated, grey = last reported

C — Dead reckoning

Project the vehicle forward from its last point using reported speed/bearing (or scheduled run time), then snap back when the next poll disagrees.

Truthful: partly — the bright dot is a guess. Grey ghost shows the gap.
Art: strongest — shows where the train is, not where it was.
Cost: highest — many agencies leave speed/bearing empty, so you fall back to schedule; and visible snap-backs when the guess is wrong look worse than B.

Note: B and C share all the hard machinery — both need vehicles projected onto a distance-along-shape. C is B plus an extrapolation term, so starting at B and adding C later is cheap. Starting at A and moving to B is not.
